# hino-gomi-dl

日野市が配布している「ごみ・資源分別カレンダー」PDF を配布ページからダウンロードします。
保存先はそのまま [hino-gomi-py](../hino-gomi-py) の入力になります。

配布ページ: https://www.city.hino.lg.jp/kurashi/gomi/kihon/1002863.html

## セットアップ

必要なものはありません。Python 3.10 以上だけで動きます（標準ライブラリのみ、`pip install` 不要）。

## 使い方

```
python hino_gomi_dl.py
```

```
data/
└── r8/                     年度ごとに分ける
    ├── r8.tamadaira.pdf    地区別 10 件
    ├── r8.osakaue.pdf
    │   …
    └── manifest.json       取得記録
```

`data/` はリポジトリに含めます（PDF も追跡します）。年度フォルダが分かれているので、
翌年ぶんは `data/r9/` に入り、前年ぶんはそのまま残ります。

年次更新はこの 2 行です。

```
python hino_gomi_dl.py
python ../hino-gomi-py/hino_gomi.py data/r8 -o out
```

| オプション | 効果 |
|---|---|
| `-o, --outdir DIR` | 保存先の親ディレクトリ。配下に年度フォルダを作る（既定: `data`） |
| `--list` | 取得せず、対象と取得済みかどうかだけ表示する |
| `--area ID` | 地区を絞る（例: `--area toyoda --area mogusa`）。繰り返し指定できる |
| `--edition ID` | 年度を指定する（例: `--edition r8`）。既定は配布ページの最新年度 |
| `--include-common` | 全地区共通ページ `r*.common.pdf` も保存する（下記参照） |
| `--refresh` | 保存済みのファイルもサーバに変更を問い合わせる |
| `--force` | 問い合わせもせず、すべて取得し直す |
| `--delay SEC` | ファイル間の待ち秒（既定: 1） |
| `--timeout SEC` | 通信のタイムアウト（既定: 30） |
| `--retries N` | 再試行回数（既定: 3） |
| `--quiet` | 進捗表示を出さない |
| `--url URL` | 配布ページの URL を差し替える |

```
[OK] r8.tamadaira.pdf -> data\r8\r8.tamadaira.pdf  25.7MB 新規  [令和8年版 多摩平]
[--] r8.toyoda.pdf  取得済み
新規 1 / 取得済み 9 / 失敗 0 -> data\r8
```

## 取得済みの PDF は取り直さない

**配布ページは毎回かならず読みます。**そのうえで、最新年度の保存先に既にファイルが
あるものだけを「取得済み」と判断して飛ばします。10 件とも揃っていれば、配布ページの
HTML（数十 KB）以外に転送は発生しません。

```
$ python hino_gomi_dl.py
[--] r8.higashihirayama.pdf  取得済み
[--] r8.hinohonmachi.pdf  取得済み
    …
取得済み 10 / 失敗 0 -> data\r8
```

判定は **年度フォルダごと**です。`data/r8` が揃っていても、配布ページに `r9` が現れれば
保存先は `data/r9` になり、そこは空なので 10 件とも新規ダウンロードします。
`data/r8` の有無は関係しません。

```
$ python hino_gomi_dl.py            # 配布ページが r9 に切り替わった日
[OK] r9.tamadaira.pdf -> data\r9\r9.tamadaira.pdf  25.7MB 新規  [令和9年版 多摩平]
    …
新規 10 / 失敗 0 -> data\r9
```

`--list` でも取得済みかどうかが分かります。

```
[済] data\r8\r8.toyoda.pdf     https://…/r8.toyoda.pdf     [令和8年版 豊田・東豊田・川辺堀之内・神明]
[未] data\r8\r8.tamadaira.pdf  https://…/r8.tamadaira.pdf  [令和8年版 多摩平]
計 10 件（r8）: 取得済み 1 / 未取得 9
```

年度途中で PDF が差し替えられることがあります。それを拾いたいときだけ `--refresh` を
付けてください。`manifest.json` の `ETag` / `Last-Modified` で条件付き GET を行い、
サーバが `304` を返せば（=変わっていなければ）ダウンロードしません。

| 指定 | 保存済みファイルの扱い |
|---|---|
| なし（既定） | パスの有無だけ見て終わり。通信しない |
| `--refresh` | サーバに問い合わせ、変わっていれば取得。変わっていなければ `[--] 変更なし` |
| `--force` | 問い合わせず必ず取得し直す |

`manifest.json` が無くても（手で置いた PDF でも）既定なら取得済みと見なします。
`--refresh` のときはファイルの更新時刻を `If-Modified-Since` に使います。

## 途中で失敗したら全キャンセル

1 ファイルでも失敗したら、残りは取りに行かずその場で中止し、終了コード `1` を返します。

```
[OK] r8.higashihirayama.pdf -> data\r8\r8.higashihirayama.pdf  25.7MB 新規  [令和8年版 東平山・旭が丘・富士町]
[NG] r8.hinohonmachi.pdf: 転送が途中で切れました（12345678/25767550 バイト）。もう一度実行すると続きから再開します
中止しました。残り 8 件は取得していません。取得を終えたファイルはそのまま残すので、もう一度実行すると未取得ぶんだけ取りに行きます
新規 1 / 失敗 1 -> data\r8
```

取得を終えたファイルは消しません。検証済みで中身は正しく、次の実行では取得済みとして
飛ばされるためです。つまり **もう一度実行すれば未取得ぶんだけ**を取りに行きます。
最初から取り直したい場合は `--force` を付けてください。

## ファイル名と年度

ファイル名も年度の接頭辞も決め打ちしていません。配布ページのリンクから読むので、
翌年 `r9.*.pdf` に変わっても修正は不要です。

- 保存名は配布元のまま（`r8.toyoda.pdf`）。hino-gomi-py は最後のドット以降を地区 ID にします
- 接頭辞の字数は問いません（`r9` / `a10` / `bb11` / `cx12`、数字だけの `2026` も可）
- 同じ元号で複数年度が並んでいるときは、番号の大きい方を取ります（`r8` と `r9` → `r9`）
- **元号の異なるリンクが混在する場合は止まります。**元号が変わると番号が 1 に戻るため、
  数字の大小で新旧を決められません。`--edition` でどちらを取るか指定してください

```
[NG] 配布ページを読めません: 元号の異なるリンクが混在しています（a1, r8）。--edition でどれを取るか指定してください
```

- 同じ PDF が複数箇所からリンクされていても 1 回だけ取得します
- 地区数が例年（10）と違うときは警告を出します。ページの体裁が変わったサインです

## 共通ページを既定で除く理由

配布ページには地区別 10 件のほかに全地区共通ページ `r8.common.pdf` があります。これは
カレンダー表ではないため、hino-gomi-py に渡すと変換が失敗します。

```
[NG] r8.common.pdf: 表紙から西暦（（20XX年）版）を読み取れません
```

そのため既定では保存しません。資料として要るときは `--include-common` を付けてください
（その場合、変換時は地区別だけを指定するか、上の `[NG]` を承知の上で実行してください）。

## 壊れたファイルを下流に渡さない

ダウンロード中は `.part` に書き、次を確かめてから正式名にリネームします。

| 検証内容 | 検出できること |
|---|---|
| `Content-Length` とバイト数の一致 | 転送の途中切れ |
| 先頭が `%PDF-` | HTML のエラーページを掴んでいる |
| 末尾に `%%EOF` | 破損 |

途中切れのときは `.part` を残し、再実行時に `Range` で続きから取得します（配信元は
`Accept-Ranges: bytes` に対応）。`If-Range` も送るので、PDF が差し替わっていた場合は
途中再開せず最初から取り直します。中身が PDF でないときは引き継いでも直らないため
`.part` を消します。

タイムアウトや `5xx` / `429` は指数バックオフで 3 回まで再試行します。配信元への配慮として
直列取得し、ファイル間に 1 秒空けます（取得済みで通信しないファイルは待ちません）。

## GitHub Actions で毎日取りに行く

[.github/workflows/download.yml](.github/workflows/download.yml) が **毎日 05:17 JST** に
配布ページを見に行き、**ダウンロードに成功したときだけ** `data/` を commit & push します。

保存済みのファイルがあれば通信は配布ページの HTML だけなので、平常時の実行は数秒で
終わり、変更が無いので push もしません。新年度（`r9` など）のリンクが並んだ日に初めて
PDF を取りに行き、`data/r9/` が追加された状態で push されます。

| 状態 | 動き |
|---|---|
| 取得済み（平常時） | HTML だけ取って終了。commit しない |
| 新年度が出た | 10 件取得して `data/r9/` を push |
| 途中で失敗 | ジョブが失敗（終了コード `1`）。**commit しない** |

`Actions` タブから手動実行もできます。`--refresh`（保存済みも問い合わせる）と
`--edition`（年度指定）を入力で渡せます。

- リポジトリの `Settings > Actions > General > Workflow permissions` を
  **Read and write permissions** にしてください（push に必要）
- 失敗したときは、その回に取得できていたぶんも捨てます（commit しないため）。
  次の実行で 10 件とも取り直しになります。取得できたぶんだけでも残したい場合は
  ダウンロード手順に `continue-on-error: true` を付けてください
- **スケジュール実行はリポジトリが 60 日間無活動だと自動で止まります**（GitHub の仕様）。
  push が年 1 回程度のリポジトリなので、`Actions` タブに出る通知に注意するか、
  ときどき手動実行してください

## manifest.json

```json
{
  "source": { "page": "https://www.city.hino.lg.jp/kurashi/gomi/kihon/1002863.html",
              "fetched_at": "2026-08-17T18:06:44+09:00" },
  "edition": "r8",
  "files": {
    "r8.toyoda.pdf": {
      "url": "https://www.city.hino.lg.jp/_res/.../r8.toyoda.pdf",
      "area": "toyoda",
      "label": "令和8年版 豊田・東豊田・川辺堀之内・神明",
      "bytes": 25725327,
      "sha256": "78c833f9f95dba032e119c43baed8bf00f451f90269d0487c5b7d5fc05eadbcf",
      "etag": "\"188898f-643fd927211c0\"",
      "last_modified": "Thu, 20 Nov 2025 02:37:03 GMT",
      "downloaded_at": "2026-08-17T18:06:44+09:00"
    }
  }
}
```

- 1 件取得するごとに書き出すので、途中で止まってもそこまでの記録は残ります
- `sha256` は hino-gomi-py が出す JSON の `source.sha256` と一致します。どの PDF から
  変換された JSON なのかを後から突き合わせられます
- hino-gomi-py はディレクトリ内の `*.pdf` だけを読むため、このファイルが同居していても
  影響はありません
